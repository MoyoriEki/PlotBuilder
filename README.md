# PlotBuilder

漫画・物語のプロットを自由座標のキャンバス上で配置・組み換えするWebアプリ「プロットボード」。テキストメモ(ブロック)・画像オブジェクト・手書きを同じ盤面に置ける。

- 本体: `plotboard.html`(単一HTMLファイル・ノービルド)
- 公開URL: https://moyorieki.github.io/PlotBuilder/plotboard.html (GitHub Pages / mainへのpushで自動デプロイ)

## 設計方針

- 軽量・直感優先。D&DはPointer Eventsによる自前実装
- **自由座標(Phase 5〜)**: マス目という概念は廃止した。盤面は連続した座標(board-px)で、アイテムは好きな位置・好きな大きさに置ける。スナップは一切しない。`UNIT`(=24 board-px)は旧データ換算と各種既定値の基準であって、スナップ単位ではない
- **重なりは許容**: 「置ける/置けない」判定は無くなり、アイテム同士は自由に重ねられる。前後関係は`items`配列の並び順(＝DOM順)で表し、ツールバーの⤒/⤓で最前面・最背面へ動かす
- **縦長ファースト**: モバイル(スマホ/タブレット縦持ち)を主要ユースケースとし、初期盤面は縦長(288×576 board-px)。今後のUIも縦長画面を優先して設計する
- **盤面サイズの増減**: 盤面の＋−は`BOARD_STEP`(=`UNIT`)刻み。縮小の下限は`BOARD_MIN`(アイテムを1つ置けるサイズ)で、消える帯にアイテムか手書きが載っている間は−を無効化する
- ローカル(IndexedDB)が常に一次ストレージ。Dropbox連携は任意(未接続でも全機能が使える)
- **表示倍率(ズーム)**: 標準は画面幅フィット(=100%)。PCなど広い画面では盤面が小さく端に寄りがちなので、右下のズームピル(− / 倍率 / ＋)で拡大縮小できる。倍率は`scale`(board-pxあたりの実px)に掛けるだけなのでD&D等の座標計算はそのまま整合する。ブロック内の文字・マーク・その場エディタも`grid`に載せた`--zoom`CSS変数(`font-size: calc(… * var(--zoom) * var(--fscale))`)で倍率に追従して拡大する。倍率は端末ローカル設定(localStorage`pb_settings`の`displayZoom`)で作品ファイルには紐づかず、端末ごとに最後の設定を保持する。PCは`Ctrl/⌘ + ＋/−/0`とCtrl+ホイールにも対応
- **ブロックの文字サイズ設定**: 設定(⚙)のスライダーで50〜200%(5%刻み)を数値指定。ドラッグ中も即時反映。`--fscale`CSS変数として`--zoom`に掛け合わせる。端末ローカル設定(`pb_settings`の`fontScale`、数値)で作品JSONには含めない。旧4段階のキー文字列(`small`等)は`FONT_SCALES`で数値へ読み替える
- **マーク(★/⚑/×)バッジ**: ブロック左上角にem基準でまたがらせ、`layoutItem`がバッジ幅のフロートスペーサー(`.mark-pad`)でタイトル1行目だけを避けさせるので文字と重ならない(`text-indent`だと入りきらない文字が横にクリップされるためフロート方式)
- **プリセット色のカスタマイズ**: 設定(⚙)からプリセット8色それぞれの色を変更できる。ブロックは`class="color-<id>"`で色を受け取るので、上書き分だけを`<style>`に注入すればブロック・スウォッチが即座に再着色される(再描画不要)。背景色を1つ選ぶと枠線・文字色はHSLを暗くして自動導出。上書きは端末ローカル設定(`pb_settings`の`palette`)として全作品共通で保持し、色ごと/一括でデフォルトに戻せる(作品JSONには含めない)
- **タイトル/メモ統一(Phase 3.5〜)**: ブロックのテキストは単一の`text`フィールド(データモデルversion 2)。1行目をタイトルとして強調表示し、2行目以降はブロックの高さに入る分だけ表示する(ブロックを大きくする＝メモが多く見える)。編集はモーダルではなくブロックに重なるその場ポップオーバーエディタで行う
- **ブロックは「テキストメモを置く手段」に格下げ(Phase 5)**: 盤面の主役はアイテム全般で、ブロックはそのうちテキストを持つ種類、という位置づけ。画像はブロックの添付ではなく独立したアイテムになった
- **下地は書けるキャンバス(Phase 5)**: 方眼の代わりに手書きインク層(SVG)を敷く。左下の道具ドックでペン/消しゴムに切り替え、下地に直接メモを書ける。目安の罫線(無地/方眼/ドット)は設定から選べる**飾り**で、スナップ先ではない

## データモデル version 5(Phase 5)

盤面から「マス目」を無くし、ブロック中心の構造を「アイテム」中心へ作り替えた版。

```jsonc
{
  "version": 5,
  "title": "作品名", "updatedAt": "ISO文字列", "device": "dev-xxxx",
  "boards": [{
    "id": "board-1",
    "size": { "w": 288, "h": 576 },     // 盤面の大きさ(board-px)。旧 grid.cols/rows の後継
    "items": [                           // 配列順 = 重なり順(後ろが手前)。旧 blocks の後継
      { "id": "blk-…", "type": "block", "x": 0, "y": 0, "w": 48, "h": 48,
        "text": "1行目がタイトル\n2行目からメモ", "color": "green", "marks": ["star"] },
      { "id": "blk-…", "type": "image", "x": 120.5, "y": 36, "w": 102, "h": 144,
        "name": "img-xxxxxxx.webp" }     // img/ 内のファイル名。1オブジェクト=1画像
    ],
    "strokes": [                         // 下地への手書き。アイテムより下のレイヤ
      { "c": "#333a40", "w": 3, "p": [12, 20, 18.4, 25.1, …] }  // p = x,y の平坦な点列
    ]
  }]
}
```

- 座標・寸法はすべて連続値(board-px)。JSONを膨らませないよう小数第1位で丸めて保存する
- アイテムは`type`で分岐する。`block`=テキストメモ、`image`=画像オブジェクト。ブロックは`images`を**持たない**(画像はもうブロックに紐づかない)
- **マイグレーション v4→v5**: `grid.cols/rows` × `UNIT`(=24) → `size`、`blocks` → `items`(座標も`UNIT`倍)。見た目の寸法は変わらない。ブロックに添付されていた画像は独立オブジェクトへ切り出すが、既存ブロックの上に重ねると内容が隠れるので**盤面の右側に新しい帯を作り、元の縦位置の順で並べる**(重なりゼロ・取りこぼしゼロを優先)。テキストが空で画像だけだったブロックは器としての役目が終わるので残さない
- v1→v2(`text`統合)、v2→v3(`images`)、v3→v4(グリッド細分化)からの段階変換も従来どおり通る。変換前の生データはIndexedDBの`docs`ストアに`v{n}-backup:{タイトル名}`として退避(消失事故防止)
- **注意**: v5のJSONを旧バージョンのアプリで開くと盤面が空に見える(`grid`/`blocks`が無いため)。Dropbox同期は Last-Write-Wins なので、複数端末で使っている場合は**全端末を更新してから**開くこと
- 設定(エディタの確定キー、下地の目安線、ペンの色・太さ等)は端末ローカル(localStorage`pb_settings`)。作品JSONには含めない

## データモデル version 3(Phase 4・履歴)

- ブロックの`thumb`(未使用)を廃止し、`images`(画像ファイル名の配列・空配列可)を追加。**配列の1枚目=ブロックに表示されるサムネイル**(エディタの「サムネに設定」で先頭に移動)
- マイグレーション: v2→v3は`images = thumb ? [thumb] : []`(thumbは常にnull運用だったため実質全ブロック`[]`)。v1→v2(`text = title + "\n" + memo`)からの段階変換。旧バージョンのデータ(ローカル・Dropbox)は読み込み時に自動変換し、変換前の生データはIndexedDBの`docs`ストアに`v1-backup:{タイトル名}`/`v2-backup:{タイトル名}`として退避(消失事故防止。Phase 2→3のマイグレーションと同方針)
- 設定(エディタの確定キー等)は端末ローカル(localStorage`pb_settings`)。作品JSONには含めない

## 下地の手書き(Phase 5・将来の自分向けメモ)

- **描画方式**: `<svg id="ink">`に`<path>`を1ストローク1本ずつ積む。座標は盤面座標そのままで`viewBox`に載せるので、**ズームしても線が滲まず、拡大縮小時の再ラスタライズも要らない**(canvasだと最大サイズ制限にも当たる)。アイテムより下のレイヤ(`z-index: 0`)＝下地の一部
- **点の間引きと平滑化**: 実px換算で`INK_MIN_SEG_PX`(2.2px)未満の移動は捨て、`getCoalescedEvents()`で取りこぼした中間点を拾う。描画は中点をアンカーにした二次ベジェでつなぐ
- **モード**: 道具ドック(左下)の✋選択 / ✎ペン / ⌫消しゴム。ペン系の間は`#grid`に`mode-ink`が付き、アイテムを`pointer-events: none`にして下地のイベントだけを見る
- **タッチ**: ペン系は`touch-action: none`にして指1本で描く。ブラウザのパンが効かなくなるので、**2本指のときは描画を中止して自前で`scroller`をスクロールさせる**(`inkPan`)
- **消しゴム**: ストローク単位。触れた線をまるごと消す(部分消しは持たない)。当たり半径は`ERASER_R_PX`(実px)を`scale`で盤面座標へ換算
- **取り消し**: ペンバーの↶で直前の1本を戻す。それ以上は消しゴムで消す方針(汎用undoは将来課題)
- **ペンの色・太さ**: 端末ローカル設定(`pb_settings`の`penColor`/`penWidth`)。太さは board-px なのでズームに追従して太くなる

## 画像の仕様(Phase 4 → Phase 5で独立オブジェクト化・将来の自分向けメモ)

- **画像はアイテム**: ブロックの添付ではなく`type:'image'`のアイテム。1オブジェクト=1画像で、枠は`object-fit: contain`なので歪まない。枠も背景も持たないので「画像そのものが盤面に置いてある」ように見える(選択時だけ枠が出る)
- **追加**: 道具ドックの🖼(ファイル選択)・☁(Dropboxピッカー・接続時のみ)、クリップボード貼り付け(Ctrl+V。ポインタ位置に置く)、ファイルD&D(落とした位置に置く)、Fileviewer窓からのD&D(後述)。置くときは元画像の縦横比で高さ`IMG_PLACE_H`(=6`UNIT`)の枠を作る
- **リサイズ**: 画像は既定で縦横比を保つ(Shiftで自由変形)。崩れた枠はツールバーの⤢で元の比率に戻せる
- **削除**: アイテムを消すだけ。実ファイルは同期成功後のGCが片づける(下記)。同じ画像を参照するアイテムが1つでも残っていればGCは消さない
- **Dropboxピッカー(Phase 4.5)**: Dropbox内のフォルダを閲覧して既存画像を選ぶ(Phase 5からは選んだ画像を盤面に置く)。**直接参照はせず「ダウンロード→縮小→`img/`へコピー」**(参照を作品フォルダ内に閉じる設計＝GC・リネーム追従・キャッシュの前提を維持)。フォルダ一覧は`files/list_folder`直叩き(basePath外を見るためブリッジの`list()`不可)、ダウンロードはブリッジの`_contentDownload`、一覧サムネイルのみ`getToken()`を使う薄いラッパーで`files/get_thumbnail_batch`を直叩き
- **Fileviewerからのd&d取り込み(Phase 4.5)**: 同一オリジンの[Fileviewer](https://moyorieki.github.io/)窓とプロットボード窓を並べ、サムネを盤面へドラッグ&ドロップして取り込む(Phase 4.5では添付先ブロックへ、Phase 5からは落とした位置に画像オブジェクトとして置く)。ブラウザ制約でFile実体は別窓へ渡せないため、Fileviewerは`text/plain`にDropbox原本パスのJSON(`{source:'fileviewer', dropboxPath, name}`)だけを載せ、プロットボードがそのパスを`_contentDownload`で取得して**既存の画像追加パイプラインへ合流**(Dropboxピッカーと同じく「ダウンロード→縮小→`img/`へコピー」)。取り込み後は原本と完全に切り離され、原本を移動・リネーム・削除しても壊れない。受け側は`source==='fileviewer'`を検証し無関係な文字列・外部URLは無視。PCの2窓運用向け(モバイルは既存のファイル選択/貼り付けで足りる)
- **パイプライン**: 追加時にCanvasで長辺1024px以下へ縮小 → WebPエンコード品質0.85(WebPエンコード非対応ブラウザはJPEGへフォールバックし拡張子も追従)。元画像はどこにも保持しない。ファイル名は`img-{ランダムID}.webp|.jpg`で、作品JSONにはファイル名参照のみ入る
- **保存先**: Dropbox `/PlotBoard/{タイトル名}/img/{ファイル名}`。バイナリの送受信はストレージブリッジ標準の`save`(Blob可)/`loadBinary`をそのまま使う(ブリッジ改造なし。ブリッジ未提供でplotboard.html側が直叩きするのはrevの`files/get_metadata`とGCの`files/list_folder`のみ)
- **キャッシュ**: IndexedDBの`images`ストアにBlobで保存(キー:`{タイトル名}/{ファイル名}`)。表示はキャッシュ優先→なければDropboxからダウンロードしてキャッシュ。オフラインで未キャッシュは「オフライン」プレースホルダ(エラーにしない)。表示はobjectURLを使い回してドラッグ中の再デコードを防ぐ
- **アップロード**: 追加時はまずIndexedDBに保存して即表示し、レコードの`pendingImgs`に積んでJSON同期と同じ遅延・リトライ系統でアップロード(オフライン追加→復帰後アップロードが成立)。JSONより先に画像を上げ、参照先が欠けないようにする
- **不要画像GC**: JSONのDropboxアップロード成功直後のみ実行。いま上げたJSONのどの画像アイテムからも参照されていない`/img/`内ファイルをDropboxとIndexedDBキャッシュから静かに削除。オフライン・アップロード失敗・競合時は実行しない。参照の集計(`docImageSet`)は**v5の画像アイテムと旧形式(ブロックの`images`/`thumb`)の両方**を見る — 一度も開いていない作品レコードは旧構造のままなので、ここを取りこぼすと現役の画像を消してしまう
- **名前変更/削除への追従**: タイトル名変更でJSONと一緒に`/{タイトル名}/`フォルダをmoveし、キャッシュキーも付け替え。作品削除で画像フォルダとキャッシュも削除

## 同期仕様(Phase 3・将来の自分向けメモ)

- **構成**: [storage-bridge](https://github.com/MoyoriEki/storage-bridge)を`<script>`で読み込み(無改造)。rev取得(`files/get_metadata`)だけはブリッジ未提供のため、`plotboard.html`側に`_apiFetch`を使う薄いラッパー(`dbxMeta`)がある。保存先は Dropbox `/PlotBoard/{タイトル名}.json`
- **アップロードのトリガ**: ①編集後20秒デバウンス ②ボード画面の⟳ボタン ③一覧に戻るとき ④タブが裏に回るとき(visibilitychange) ⑤オンライン復帰(onlineイベント)・Dropbox接続時は未同期(dirty)の全作品を順次アップロード
- **競合検知**: 最後に同期したrevを作品ごとに保持し、アップロード直前に現在のrevと比較。不一致=他端末の更新 → ダイアログで「この端末の内容で上書き」「クラウドの内容を読み込む(この端末の変更は破棄)」「あとで決める(保留)」の選択。自動マージはしない(Last-Write-Wins)
- **開くとき**: クラウドのrevがローカルと違い、ローカルに未同期変更が無ければ黙ってダウンロードして置き換え。未同期変更があれば競合ダイアログ
- **オフライン時**: ローカル編集は通常どおり。名前変更・削除は同期済み作品に対しては不可(Dropbox側の反映を伴うため。「次回同期時に反映」方式はキュー管理が増えるので採用しない)。ローカルのみの作品は制限なし
- **マイグレーション**: Phase 2までの単一ボードデータは初回起動時に「無題」として取り込み。旧データ(IndexedDBの`docs`ストア)は保険として残したまま
- **インジケータ**: ローカル保存済み / クラウド同期済み / 同期待ち / 同期中 / オフライン / 競合 / 保存中
